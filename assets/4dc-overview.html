4dc — How We Build & Document Features

A repeatable cycle that separates what we're building from how it's built and proof that it works — with a paper trail every step of the way.

The Process

One Cycle, Five Phases

Each feature moves through the same five phases. Every phase produces one clear artifact, and nothing moves forward without explicit human approval.

Inside Every Phase

Nothing Ships Without a Human Saying Yes

Each phase follows the same rhythm: gather context, propose a direction in conversation, write it up for review, and stop. Work never silently proceeds — the human is always the approval gate.

flowchart TD
    S1(["Read context"]) --> S2(["Propose direction
(conversation)"])
    S2 --> S3{"Aligned?"}
    S3 -- "no, adjust" --> S2
    S3 -- "yes" --> S4["Write review.md
(objective, risks, open questions)"]
    S4 --> S5{"Approved?"}
    S5 -- "revise" --> S2
    S5 -- "yes" --> S6(["Write final artifact"])

Tracking Delivery

Every Feature Has a Visible, Provable Status

docs/roadmap.md is the single place to see what's shipped. A feature is only "Done" when its acceptance test passes and is linked — no feature is called finished on trust alone.

stateDiagram-v2
    [*] --> Planned : idea proposed
    Planned --> Partial : increment approved
    Partial --> Done : acceptance tests pass
    Done --> [*]

    note right of Planned
      Job story only.
      No commitment yet.
    end note
    note right of Partial
      Increment cycle underway.
      Tests being written.
    end note
    note right of Done
      Passing test linked.
      This is the proof.
    end note

📝 Planned

A job story exists. Nothing is committed. Can be reprioritized freely.

🚧 Partial

An increment has been approved and is actively being built and tested.

✅ Done

Acceptance test passes and is linked. This is what "shipped" means — provable, not assumed.

Why This Matters

What This Buys the Team

PrincipleWhat it prevents
WHAT before HOW before CODEBuilding the wrong thing well. Scope is locked before implementation starts.
Files are the source of truthDecisions living only in chat history or someone's memory.
Evidence over claimsFeatures marked "done" that don't actually pass their tests.
Human approval at every gateScope creep and silent, unreviewed changes.
Durable docs, promoted deliberatelyDocumentation rot — docs are only updated when something durable actually changed.
